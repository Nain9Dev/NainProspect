# Business Rules & Compliance Specification — NainProspect

## 1. Compliance Gates (RGPD & LSSI-CE)

### Rule BR-01: Discard Named Email Addresses
- **Condition**: If an extracted email address does not start with one of the authorized role prefixes (`info`, `contacto`, `contact`, `hola`, `hello`, `ventas`, `sales`, `comercial`, `administracion`, `admin`, `soporte`, `support`, `oficina`, `office`, `general`, `atencionalcliente`, `clientes`, `marketing`).
- **Action**: The email must be discarded and marked as `None`. Personal named accounts (e.g. `antonio.perez@empresa.com`) must never enter the pipeline dataset.

### Rule BR-02: Hard Email Dispatch Gate
- **Condition**: Any attempt to perform an outbound SMTP / API mail send.
- **Action**: The system must reject the dispatch and execute in simulation mode (`envio_email=SIMULADO`). Cold sending requires a signed legitimate interest assessment (RGPD 6.1.f) and opt-out registry setup.

### Rule BR-03: Deterministic Legal Footer
- **Condition**: Rendering of any outreach email template.
- **Action**: The legal footer must be generated deterministically from `SENDER_COMPANY_NAME`, `SENDER_LEGAL_ID`, `SENDER_ADDRESS`, and `SENDER_OPTOUT_EMAIL`. It must never be generated by LLM prompt hallucination.

## 2. Classification & Scoring Rules

### Rule BR-04: Target Size Band
- Target company size is 50 to 500 employees (`mediana`).
- When headcount is undeclared, the model estimates the band and marks `confianza: baja`.

### Rule BR-05: Priority Scoring (1 to 5)
- **Priority 5**: Medium company (50-500 employees), relevant industry, valid role-based email present.
- **Priority 3-4**: Valid industry, probable size match, or missing direct email.
- **Priority 1-2**: Micro / small (<50) or massive (>500) enterprise, non-target sector.

### Rule BR-06: Telegram Alert Gate
- Telegram notifications are triggered only for leads with `prioridad >= 4`.
- When Telegram credentials are not configured, output falls back to console logs without raising an error.
